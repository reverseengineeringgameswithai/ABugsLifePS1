# Collision and floor planes

## Canon conclusion

Original-game collision is a resident, scene-populated sector-and-plane system.
It is not the visible terrain mesh and it is not a scalar floor-height table.
The load path converts verified `LEVEL*.RAW` collision chunks into a runtime
sector table; player integration selects signed 32-byte plane records into
per-use scratch, performs a swept plane crossing/face test, and commits resolved
XYZ plus floor/ground state.

Authoritative machine evidence is `analysis/phase4_collision.json` (SHA-256
`d1987d886559928ba48ba8dae9c97157ad25fdec3c9233311b427fba8cdf9399`),
generated by `tools/phase4_collision.py` from the pristine executable, pinned
staged assets, pristine saves and the hash-verified retail CUE/track. ALLMODS and
`fall_through_floor.sav` were not used as original-game authority.

## Runtime structures

The sector table begins at `0x800A7E48`, uses `0x30`-byte rows and takes its
active count from `0x800822A0`.

| Offset | Type | Meaning |
|---|---:|---|
| `+0x00/+0x04/+0x08` | `s32` | world origin X/Y/Z |
| `+0x10` | `u32` | scene-local block pointer |
| `+0x14/+0x1C` | `s32` | broad-phase minimum X/Z |
| `+0x24/+0x28` | `s32` | broad-phase extent X/Z |
| `+0x2C` | `u16` | sector flag |
| `+0x2E` | `s16` | region code |

The collision plane record is `0x20` bytes:

| Offset | Type | Meaning |
|---|---:|---|
| `+0x00/+0x02/+0x04` | `s16` | plane normal X/Y/Z |
| `+0x06/+0x08/+0x0A` | `s16` | reference point, scaled by 32 at use |
| `+0x0C/+0x0E/+0x10` | `s16` | complete XYZ vector from V0 to V1 |
| `+0x12/+0x14/+0x16` | `s16` | complete XYZ vector from V0 to V2 |
| `+0x18/+0x1A` | `s16` | X footprint minimum/extent |
| `+0x1C` | `s8` | packed Y-footprint minimum delta, scaled by 64 and added to V0.y |
| `+0x1D` | `u8` | packed Y-footprint extent, scaled by 64 |
| `+0x1E/+0x1F` | `s8` | packed Z footprint terms |

The XYZ edge layout is consumed literally by `0x80032610`; it is not three
interleaved X/Z deltas. The player builder reads `+0x1C/+0x1D` at
`0x800368A0..0x800368DC` (the pointer is biased to record `+0x1D`), so the old
"unread" classification was false. The separate entity/projectile selector may
omit this Y gate, which caused the earlier overgeneralization.

Negative normal Y identifies the observed floor/slope orientation because
negative world Y is up. Other orientations use the same record type; there is
no separate wall discriminator in the record.

Player candidate count is `u32` at `0x80082314`, pointers are `u32[]` at
`0x8009C230`, and owning sector IDs are `u16[]` at `0x80091718`. The player path
inside `0x8003633C` builds its own list. `0x80037320` is the separate shared
entity/projectile builder, not the player-list owner.

## Producer and consumer chain

1. `0x80030F60` converts decompressed source rows into the runtime table.
2. `0x800313A8` builds sector AABBs/grid membership. Its decoded scan bound is
   700 sectors.
3. `0x8003633C` clears and populates player candidate scratch from the current
   position, sector AABBs, block groups and record footprints.
4. `0x80035F24`, `0x800345CC` and `0x80035280` apply the appropriate resolver
   passes; the observed ordinary player branch entered `0x80035280`.
5. Resolved X/Y/Z are committed at `0x80036CE8/0x80036CEC/0x80036CF0`;
   `0x80036D54` performs the separate probe-bias Y restore.
6. `0x80038F38` returns the current sector's signed `+0x2E` region code only
   when the supplied gate byte equals 1.

Ground-height/spawn queries, player physics, movers, camera collision callers,
checkpoints and region/exit logic consume this substrate. Their downstream
policy remains owned by their respective systems.

## Direct causal controls

From pristine `level01.sav`, twelve Up frames produced player/floor Y
`2715/2844`.

- Adding `+2048` to active sector 99 origin Y produced `4785/4908`: deltas
  `+2070/+2064`, still grounded (`257`).
- Adding the same delta to distant non-candidate sector 0 left X/Y/Z, floor Y
  and grounded state exactly equal to baseline.
- Adding `+64` to the reference Y of all six current-sector floor planes (the
  record value is scaled by 32) again produced `4785/4908`, still grounded.

These are two independent positive controls and one spatial negative. The
small 6/16-unit difference from the nominal 2048 is the timing-matched movement
and collision response, not an assumed scalar-floor equation.

## Breadth and region codes

The retained run read every row from Training, stages 1–15 and three bonus
contexts: 19 distinct table hashes, counts from 46 to 634. Eighteen ordinary
contexts reached the exact player candidate boundary with 2–27 candidates; the
Riverbed Flight context retained a valid 380-sector table but bypassed that
ordinary boundary. Unique samples included 165 floor/slope planes and eight
other-orientation planes. The nonzero region-code domain across the tables was
exactly `{1,2,3,4}`.

From pristine `level01_end_of_stage.sav`, held Up reached sector 177 naturally
after 54 frames. Its origin is `(-163008,-169888,-124832)`, its region code is
2, and the transition lever `0x800823A0` became 1. At that natural sector,
`0x80038F38` returned 2 with gate 1 and 0 with gate 0.

## Lifecycle and capacity

- Pause froze X/Y/Z, floor Y and grounded; resume rebuilt live response.
- Native same-scene death decremented lives and restored health 4.
- LEVEL01 and LEVEL02 have different table hashes; unloading and reloading
  LEVEL01 restored the exact prior table hash. All table rows and plane pointers
  are therefore scene-local contents even though their storage addresses are
  resident.
- The pointer span from `0x8009C230` to the adjacent known pool at `0x8009C870`
  contains 400 `u32` slots. The append at `0x800368E8` increments count without
  a bounds check. Treat 400 as a fail-closed validator ceiling, never as a safe
  authored target; a MOD asset must prove its maximum simultaneous candidate
  count remains below it.

## Boundaries

[[SYS_render_collision_source_separation]] remains controlling: E01 owns
visible terrain. E04 owns camera behavior, E08 mover policy, E10 hazard/damage
policy, stage rows own objectives, and the loading/overlay family owns
transition dispatch. E02 provides typed collision and region inputs to those
consumers without inheriting their behavior.

## Authoring WALLS on this substrate (2026-08-11)

Authored near-vertical collision needs **no new record type and no wall discriminator** — the
statement above ("other orientations use the same record type") is now exercised by a MOD.
LEVEL01's own chunk-32 carries **682 planes above 84°** out of 6,379 (plus 1,271 at 60–84° and
284 with `ny > 0`, i.e. overhangs), all `|n| = 0x4000` with `ny` slightly negative and small X/Z
footprints. Authored walls are emitted in exactly that class.

Two facts settle how to produce them from a heightfield:

- **Orientation is free.** For a single-valued surface the upward normal is `(f_x, -1, f_z)`; its
  horizontal component is the gradient, which points DOWNHILL — back at the low ground the player
  approaches from. The `heightfield_collision` convention (force `ny <= 0`) therefore yields
  inward-facing walls automatically. Measured on an authored ring: 503/503 near-vertical planes
  face inward, zero exceptions.
- **The failure mode is RESOLUTION, not encoding.** A uniform tile does not lose a step narrower
  than its pitch; it spreads the same rise across the whole tile, so the face is shallower than
  authored (80.2° vs an authored 85.6°) and lands up to a tile-width from the authored edge.
  `tools/surface_cells.py` splits cells anisotropically to recover the authored angle.

⚠️ A wall only exists where `emit_floor_planes` actually authors a sector: selection is sector
origin within `PLAY_HX/HZ` (3600) of the spawn. Outside that band the sector keeps pristine
collision, so the wall renders and is walk-through.

Evidence: `docs/G3_NATIVE_AUTHORED_CLIFF_WALLS.md`, `tests/test_cliff_walls.py`,
`tools/validate_arena_cliff_wall.py` (in-game A/B: same DAT + EXE, authored vs pristine
`LEVEL.RAW` — Flik stops at the authored corner vs walks 1,138 file units past it).

## ⚠️⚠️ OVERLAPPING SECTOR BLOCKS CONTRADICT EACH OTHER OVER RELIEF (2026-08-11)

Authored collision blocks **overlap**: `heightfield_collision.mesh_block` builds each sector's block
over a ±1300 file-unit half-extent (`emit_floor_planes.TILE`) while sector origins are spaced closer
than 2600, so **3–6 sector blocks cover the same XZ**. Each samples the surface **on its own tile
grid**, and those grids are offset from one another.

* Over a **flat** surface every block returns the same height — spread exactly **0**.
* Over **relief** they disagree, and the disagreement grows with how fast the surface moves.

Measured with `tools/probe_floor_vs_collision.py` (offline; lists every plane whose XZ footprint
covers a point):

| build | spread at spawn (4250,16050) | worst sampled | traversable |
|---|---|---|---|
| `ABL_ARENA_CLIFF_LIT` flat | 0 | 0 | yes |
| `ABL_HILLS` wave 2200 | 3,104 rt (97 file) | 6,688 rt (209 file) | yes |
| `ABL_ONEPAY` wave 1600 | **6,304 rt (197 file)** | 9,888 rt (309 file) | **no — falls through** |

At the `ABL_ONEPAY` spawn there are floor planes at runtime Y **−20224, −15488, −13920** from
sectors 45, 107 and 108 — three mutually contradictory floors, each internally consistent (the two
triangles of one quad share a Y).

**Predictor.** P11 places Flik at `collision floor Y + 3200` (movement-integrator body offset). When
the spawn stack spread exceeds **3,200 runtime** the highest contradictory plane sits above his head,
he starts inside geometry with nothing under him, and he falls (`smoke y_max 78496`). Keep the spawn
stack spread **under 3,200 runtime / 100 file units**. Measured across three builds — a predictor
with a mechanism, not a proof. ⚠️ `ABL_HILLS` cleared it by 96 runtime units (3%), so the working
hills build was far closer to this failure than it looked.

**Refined mechanism.** `emit_floor_planes` retiles each sector over **its own pristine bbox** with a
fixed `replace_tile_n=16`, and sector bboxes differ — so **every sector gets a different tile pitch**
and samples the same relief at a different resolution. (Sector 107's block covers a point 2,579 file
units from its origin, so replaced blocks are nowhere near the ±1300 `TILE` half-extent used for
from-scratch flat sectors.)

## ⚠️⚠️ AUTHORED TILE PITCH MUST BE A MULTIPLE OF 64 (2026-08-11)

A plane record's **Z footprint extent quantises to 64 file units** (`Plane.from_fields`:
`extz_hi = round(extz / 64)`). Any authored pitch that is not a multiple of 64 encodes a footprint
SHORTER than its own cell and leaves an **uncovered crack** between adjacent cells — invisible in
every static check except a fine coverage sweep, and Flik falls through it.

Measured: pitch 600 (= 9·64 + 24) opened **two 23-unit cracks** along one Z line through the hills
arena; pitch 576 (= 64·9) opened **zero**. `surface_cells._lattice_edges` now raises on a
non-multiple; `tests/test_overlapping_block_agreement.py` pins it. The guard immediately caught that
that test's own pitch (162) was invalid while the test had been "passing".

This applies to ANY authored pitch, latticed or not.

## ✅ SHARED COLLISION LATTICE — ADOPTED at pitch 640 (2026-08-11)

`--collision-lattice PITCH` snaps **every** authored block's cut lines to the shared world lattice
`k * PITCH` instead of splitting each block's own bbox into `--replace-tile-n` parts, so overlapping
blocks sample identical corners. Default `None` is byte-identical to the old path.

Validated against a **byte-identical control** (`ABL_HILLS_CTRL`: same scene, no lattice — RAW and
smoke walk identical to `ABL_HILLS`), so the lattice was the only variable. Pitch sweep, all ×64
except 600:

| pitch | chunk-32 | spawn spread | worst spread | cracks | smoke WALK | arena |
|---|---|---|---|---|---|---|
| none | 296,924 | 1,120 | 6,688 | 0 | moved 124,344, y_max −10,725 | — |
| 600 | 301,084 | 992 | 128 | **2 × 23 u** | y_max **+71,266** | — |
| 576 | 309,340 | 1,984 | 1,920 | 0 | y_max **+94,914** | — |
| 320 | **440,732** | 0 | 0 | 0 | not booted (past ceiling) | — |
| **640** | **293,212** | **0** | **0** | **0** | **y_max −9,757** | **contained=True** |

**Pitch 640 wins on every axis at once**: chunk-32 *smaller* than baseline, disagreement exactly 0,
no cracks, smoke 4/4 with Flik on the ground, and `validate_arena_cliff_wall` PASS — contained in both
driven directions, both stopped by an authored wall, no plunge.

**Why 640 and not 576 is unexplained.** Both are ×64, but only 640 drives disagreement to exactly 0,
and only the 0 case is walkable. 320 also reaches 0 but triples chunk-32 past the boot ceiling. The
working rule is empirical: **sweep the pitch, take one measuring 0 disagreement that fits the
chunk-32 budget** — both checks are offline (`tools/probe_floor_vs_collision.py`) and cost seconds.

⚠️ **A PARTIALLY aligned lattice is worse than none.** The baseline has the worst spread of any build
(6,688 rt) and walks fine — its blocks disagree but each is self-consistent and the selector copes.
Among latticed builds spread is sharply predictive (0 walks, 1,920 falls). Never ship a pitch that
measures above 0.

**New chunk-32 data point: 309,340 B boots and passes smoke**, raising the proven-good ceiling from
296,924. 315,228 remains known-fail, so the live band is now narrow.

Evidence: `docs/COLLISION_LATTICE_ATTEMPT.md`.

**Fix, proven at block level, NOT yet wired in.** `surface_cells.cells(..., lattice=P)` snaps every
block's cut lines to the global `k * P` lattice; `heightfield_collision.mesh_block` passes it
through. Two overlapping blocks with pitches 162 and 300 disagree by **3,680 runtime (115 file)**
historically and by **0** with the lattice — `tests/test_overlapping_block_agreement.py`.
`lattice=None` is byte-identical to the old path, so no existing build moves. Adopting it means
choosing one world pitch for the level and re-measuring the spawn stack spread before a disc run.

Evidence: `docs/PAYLOAD_CULL_AND_REANCHOR.md`, `tools/probe_floor_vs_collision.py`.
