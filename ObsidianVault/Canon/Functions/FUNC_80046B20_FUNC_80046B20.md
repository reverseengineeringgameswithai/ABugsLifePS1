# FUNC_80046B20 - FUNC 80046B20

## Purpose

**The level-load player-spawn writer** (GAP-0035 layer 1). Signature **`FUNC_80046B20(a0 = player_block, a1 = scene_index)`** — fills the 168-byte player block `0x800a6500` from a **resident EXE start table** at `0x80077314 + index*12`. Located via a runtime WRITE-watch + execTrace → [[Experiment - Initial spawn write-watch]]. Lives in the level-load/init region (sibling of the LEVEL.RAW loader [[FUNC_80046330]]); called from scene-init [[FUNC_8005B714]].

## Second half (2026-08-03): C04 enemy-elimination quota constructor

Immediately after filling the player block, the SAME function (`0x80046c10..0x80046c74`,
still within the exact 396-byte bound `0x80046B20..0x80046CA8`) zeroes then rebuilds the
per-level enemy-elimination quota at player `+0x8E` (`0x800A658E`, [[SYS_enemy_death_and_permanence]]):

1. `0x80046c10`: `sh zero,0x8e(s3)` (`s3` = the player block itself) zeroes the quota.
2. A 64-iteration loop walks the enemy actor pool at `0x8009FD80`, stride `0x84`.
3. Per slot: skip if `id` (`+0x00`) is `0` (empty); skip if flags `+0x5C` `& 0x08A0 != 0`;
   otherwise increment the quota by 1.

Live-confirmed via `accessLog`: four writes to `0x800A658E` at PC `0x80046c64`
(`sh v0,0x8e(s3)`), same emulator frame, values stepping `0→1→2→3→4`. Cross-checked against
two different level saves: `level01.sav` quota `4` (matches the trace exactly), `level02.sav`
quota `50` — confirming a genuinely per-level computed total, not a fixed constant.

The exclusion mask `0x08A0` shares its `0x80`/`0x20` sub-mask with D14_wasps_dragonflies'
own homing-berry non-targetability filter (`analysis/phase4_d14_wasps_dragonflies.json`,
bits `0xA0` rejected there too) — plausibly the same underlying "is this a real, killable
enemy" flag.
Bit `0x0800`'s meaning is NOT confirmed; a boss-exclusion hypothesis was not tested live. Full
detail: `analysis/phase4_c04_enemy_token.json`,
[[EXP_2026-08-03_phase4_c04_enemy_token]].
