# SYS_function_census

## Purpose
ONE canonical, committed, machine-readable inventory of every function in the
game — resident EXE plus all 20 analyzable overlays — replacing "whatever r2
`aaa` happens to find" with a multi-signal census. This is the ground truth the
decomp substrate (`split_exe.py`), Ghidra cross-checks, and dynamic traces key
off. Canonical data: `analysis/functions.json` (+ `.csv` projection,
`code_coverage.md` report). The cross-artifact status summary is
`analysis/re_campaign_status.json`; verify it with
`python tools/re_campaign_status.py --check`. Regenerate the census with:
`python tools/re_baseline.py --all && python tools/function_census.py`.

## Method (signals; each function records which found it)
symbol (`re_symbols.sym`; `*_OBJ_*` interior labels excluded) · entry ·
r2 `aflj` · PsyQ signatures · Ghidra · jal_target
(exhaustive opcode-3 scan) · j_target · prologue (`addiu sp,-N` + `sw ra`) ·
jumptable (targets read from the known jr-dispatch tables) · reachable (BFS from
entry + table roots) · gap_code (uncovered outgoing-jal sites prove r2-truncated
continuations) · dynamic (trace hits, Phase 4). False-positive filters: string
ranges, known data anchors, alignment/bounds.

## Key modeling rules
- Census key = `(space, overlay, start)` — same-VA collisions across swapped
  overlays are legal and expected.
- LEVEL*.BIN code starts at region base **+4** (`[+0]` = header/ID word);
  r2 hits at the bare base are remapped (the known first-pass landmine).
- Known data anchors (`0x8001B1C0/2F4/3C4/828`, `0x8007FD00`) can never be
  swallowed by or start a code range (test-enforced).
- Jump-table CASE blocks are NOT standalone ABI functions (the old B17 lesson);
  jr-dispatch targets carry a `jumptable` tag + table name in notes instead.
- `gap_code` ranges are honest continuations: r2 `realsz` truncated at a
  jr-table, but uncovered outgoing `jal` sites prove live code; boundaries
  flagged imprecise.
